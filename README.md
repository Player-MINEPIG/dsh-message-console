# 看点什么 · DSH Message Console

面向个人使用的 DSH 消息聚合插件。以“来源”为配置单位，把评论、issue、PR 和 release 的变化集中到一个入口，分别管理阅读状态、后续处理与发布审核。

**当前是开发版本。** 已支持基于 Chrome Cookie 的 B 站视频评论和 GitHub 仓库只读采集。真实采集已验证；Cookie连接器暂不提供发布，真实订阅模型与完整自动处理链路仍需验收。

## 已实现

- 主面板总览按平台与来源展示卡片，支持独立平台列表、来源展开和来源详情页。来源可保存简介与标签。
- 来源配置、适用范围明确的全局默认值与来源覆盖。抓取和整理默认分别每 6 小时执行，可手动刷新并整理。
- 首次抓取作为已读基线；后续变化按内容版本显示未读，个人处理状态独立保存。
- 评论经 Jev 概率判断分流；人工介入不提前拟稿；模糊判断最多升级一次。
- PR/issue 分析、回复生成与独立监督会话。监督拦截后保留草稿和原因，不自动重试改稿。
- 对外发布均需人工批准，绑定草稿正文及来源版本；发送结果不确定时保留 `unknown`，不自动重发。
- 每个工作角色使用独立 DSH 会话；人工入口携带真实背景消息；Jev 输入输出在插件里可查。
- GitHub 公开仓库 REST 读取连接器，支持分页、限流退避和 PR head 变化检查。PR 目前只获得 patch 和讨论，不代表完整代码审查或实际执行测试。
- 原子文件持久化、进程锁、中断状态恢复、宿主认证保护的 API。

## 本地开发与预览

Node.js `^22.19.0 || >=24`，DSH `0.2.1-rc.2`，Cordis `4.0.5`。本版本仅声明这一宿主组合的兼容性，不自动升级宿主或迁移已有数据。

```sh
npm ci
npm run check
npm run demo
```

打开 `http://127.0.0.1:3147`。预览使用合成数据和模拟模型，不读取真实账号，不发送消息。每次启动创建独立模拟数据目录；数据、构建临时文件都留在被 Git 忽略的 `.local/`。

## DSH 开发安装

先在隔离的开发 profile 验证。需要已启用的 DSH Agent/会话持久化/Web 服务、标准 `dsh-prompt-assembler` 精确版本 1.1.1（[发布标签 `v1.1.1`](https://github.com/Player-MINEPIG/dsh-prompt-assembler/tree/v1.1.1)，提交 `f757ae75659e4d78cee46ab022987da6cf82fe94`），以及用户 Jev fork 0.3.6（[固定提交 `2ec0510`](https://github.com/Player-MINEPIG/dsh-jev-plugin/commit/2ec0510ffcdabe790df8c93b0b40aee07b93c342)）。

安装 npm 依赖本身不等于在宿主中启用了对应服务。

Assembler 1.1.1 从“插件 → 已安装插件 → dsh-prompt-assembler → 配置当前会话”打开装配编辑器。控制台使用标准 native 后端，不需要核心扩展。本次由同版本的旧源码提交 `003e73f` 更新至上述正式发布包，lockfile 固定 npm 包的完整性摘要。

已有 Assembler 或 Jev 时更新并复用同一个实例，消息插件只调用共享的 `decisionModels.ask`，不另存 Jev URL 或密钥。

```sh
npm run build
npm pack --pack-destination .local
dsh plugin --profile YOUR_DEV_PROFILE add "dsh-prompt-assembler@1.1.1"
dsh plugin --profile YOUR_DEV_PROFILE add "dsh-jev-plugin@https://codeload.github.com/Player-MINEPIG/dsh-jev-plugin/tar.gz/2ec0510ffcdabe790df8c93b0b40aee07b93c342"
dsh plugin --profile YOUR_DEV_PROFILE add /absolute/path/to/dsh-message-console/.local/dsh-message-console-0.1.0.tgz
```

包携带 `cordis.patch.yml`，默认将插件数据放入该 profile 的 DSH 数据目录。可在插件配置中指定：

| 配置 | 用途 |
| --- | --- |
| `storageDir` | 本插件的数据目录；单进程独占 |
| `cookieFile` | 显式导入的本机Cookie文件路径；不通过状态API返回凭据 |
| `autoSchedule` | 是否启动抓取/整理计时，默认 true |
| `timeoutMs` | 单个生成 Agent 的取消期限，默认 300000 |

从 DSH 左侧插件区域打开“看点什么”，在“全局配置”从宿主目录选择提供商与模型，在“添加来源”绑定已有工作区。`dsh-plugin-subscriptions` 通过宿主 LLM 提供商接口复用，不单独保存供应商凭据。Jev profile 不配置时使用 Jev 默认 profile；若其输出只有选项而无完整概率，插件会记录失败，不冒充获得置信度。

Jev fork 0.3.6 的 native 普通模型和 custom 路径均已用合成输入验证完整概率、低置信升级、失败记录和人工审核边界。native 的概率是模型自报估计，不是 token 概率或经过校准的置信度；阈值仍需真实样本验证。工作记录保留 Jev 返回的 profile、model、answers 和 usage，不推测服务未提供的概率来源 metadata。未使用真实 Jev 凭据。订阅提供商仍由宿主目录接入，但第三方提供商插件也必须兼容该宿主。`dsh-plugin-subscriptions` 0.9.9 的 peer 声明尚不包含 `0.2.1-rc.2`，本轮未验证其真实订阅调用，不应强行跳过依赖检查。

工作模型和监督模型可以使用不同 provider/model；即便使用同一模型，也分别创建独立会话。任务插件不是依赖；Memory Manager 不作为硬依赖。

## 账号与目前限制

- 配置 `cookieFile` 后，两平台均使用导入的Chrome Cookie。GitHub读取网页中的结构化列表、讨论与diff；B站读取视频根评论及逐根分页回复。Cookie连接器只读，`canPublish`始终为false。
- macOS可显式运行 `node scripts/import-chrome-cookies.mjs .local/credentials/chrome-cookies.json`。默认Chrome的Default profile，可将 `"Profile 1"` 作为第三个参数。仅导入两站必要Cookie，钥匙串密码只留在进程内；文件权限0600。该脚本不会创建PAT/OAuth凭据，不会自动续期；失效后需重新导入。
- GitHub网页的延迟加载讨论可能不完整，连接器会标注上下文限制并停止该项的自动分析；列表分页未完成则整轮不提交基线。过大的diff同样标注限制。Cookie方式暂不支持Release，未配置Cookie时仍可匿名REST读取公开仓库。
- 公开仓库读取目前按完整快照扫描，较大仓库会产生较多请求；限流后保留已有数据，未完整获取不会推进基线。尚无增量缓存。
- PR 缺失 patch/代码上下文、issue 缺少复现材料时，只能给出受限分析。尚未接入仓库检索、运行测试或自动修改代码。
- `unknown` 发布结果需要人工去原平台核实；本版没有自动对账和恢复发送的界面。
- 已验证真实账号只读采集及隔离宿主调用；完整默认profile和实际订阅模型的处理链路尚未端到端验收。

### 无浏览器的 VPS

Cookie 连接器运行时不需要 Chrome。可在自己的 macOS 上显式导出，经安全通道传到 VPS 上 DSH 运行用户的私有目录，设置权限 `0600`，再将 `cookieFile` 指向该文件。连接器每次请求重读文件；登录失效后需在本机重新登录、导出并替换。VPS 的出口 IP 是否被平台接受、Cookie 有效期和风控限制需要单独实测。

迁移来源数据时还需处理工作区 ID、目录路径及真实 DSH 会话历史，不能只复制插件状态文件。先使用独立的新宿主数据目录验证，再决定是否迁移旧数据。

## 验证与扩展

`npm test` 覆盖状态、并发审核、发送不确定性、失败恢复、GitHub 协议和 HTTP 入口。开发依赖锁定上述 Jev 提交，默认运行 native/custom 共享服务到工作流与持久记录的离线测试；native 使用真实 DSH LLM 服务和合成适配器，custom 拦截 HTTP 并返回合成响应，生成与监督使用合成执行器。可使用本机 DSH 安装执行额外的离线宿主测试（不加载默认 profile 或真实模型凭据）：

```sh
DMC_DSH_ROOT=/absolute/path/to/dsh-install node --test test/host.test.js
```

宿主测试使用真实 Agent Loop、标准 Assembler、工作区、JSONL 持久化和冷会话查询，验证工具限制、输入顺序、尾部 PHI、必需运行上下文、模型目录白名单，以及成功、失败和人工会话释放后完整历史不变。模型输出来自离线合成适配器；这些检查不代替 Web 和真实账号验收。未设置该环境变量时，此测试跳过。

使用同一固定 Jev 开发依赖验证指定宿主的服务挂载、profile 目录和经宿主合成模型的调用，不读取凭据或联网：

```sh
DMC_DSH_ROOT=/absolute/path/to/dsh-install \
node --test test/host.test.js test/jev-host.test.js
```

这些测试验证合同与分流，不证明真实模型判断准确。Jev 拒绝缺失概率的响应后，本插件保留实际错误且停止后续生成；native 上游流失败在当前 Jev 中可能仅返回“native 响应不完整”，无法从 `ask` 恢复原始错误详情。

业务模型、连接器和宿主执行层分离，新增平台需要实现代码适配。详见 [架构与连接器合同](docs/ARCHITECTURE.md)。本项目采用 [MIT](LICENSE)。

### 来源与工作区

“看点什么”位于 DSH 左侧插件区域，点击后在右侧主面板展示。每个来源必须选择一个已有 DSH 工作区。分析、监督和人工处理会话均在该工作区创建，并登记到宿主工作区的会话列表。更换来源工作区仅影响新会话。工作区删除或目录失效时会停止新建工作会话，并提示重新选择；旧数据与会话链接保留。

### 视频上下文与 post-history instruction

B站来源填写视频BV号、av号或完整视频链接。每个来源可添加独立上下文、文字资料、工作区内的显式文件引用，以及可编辑的post-history补充指令。资料只读取所选工作区内的非隐藏md/txt/json/csv文件，拒绝越界符号链接；单文件128KB、总量256KB。多个来源不会因使用同一工作区而自动共享全部资料。

模型请求保留前置system数据边界，Assembler在history/input之后追加固定提醒及用户补充指令。当前native后端以真实user消息投递尾部提醒，不伪称system消息；Jev决策指令另行附加同样的边界。测试证明消息顺序与持久化，不能保证模型绝不受注入影响。平台内容及资料不插入可信指令，自动工作会话无工具权限，发布仍需独立人工审核。

### 总览与来源页面

顶栏提供“总览”“全局配置”和“添加来源”。总览首先显示综合优先级最高的最多三个已有平台，再显示来源卡片。点击“全部平台”或“展开来源”可单独浏览对应列表。点击平台查看该平台的来源，点击来源进入独立来源页。编辑来源入口位于来源页，全局配置只管理全局默认值。

未读变化按内容项计数，一条评论对话无论新增多少条回复都只计一个未读内容项。需要处理按内容项去重，包含待处理、暂后处理及尚未关闭的审核草稿。已经标记“本轮已处理”的内容不会因旧人工介入结论重新计入；仍未关闭的草稿需另外审核或暂不发布。

综合排序按当前版本的分析重要性排序，有明确依据的紧急性只作有限修正，再比较需要处理数、未读数与内容更新时间。“最近更新”使用内容的 `changedAt`，抓取时间单独显示。尚未整理或分析已过期的内容不会显示推测的摘要与重要性。

### 调整模型背景顺序

在添加或编辑来源时，可以调整“来源信息与关注规则”“上下文”“资料”“当前内容及讨论”四个数据块的顺序，也可以调整资料内部的顺序。“更新真实预览”会解析所选工作区内显式引用的文件，并装入选定的真实内容项。新来源没有实际内容时显示占位；尚未解析的文件只显示路径。

顺序保存后用于 Agent、Jev 与人工会话背景。system 任务、真实历史和尾部 PHI 的位置固定。Jev 使用独立协议，同序数据块进入 `state`，PHI 放入问题 `instructions`。预览展示数据块和固定边界，不代表模型提供商的完整请求。

顺序、上下文或资料变更会使旧草稿失效，并为后续人工处理创建新会话，旧会话自身的完整历史仍保留。“整理已有数据”会处理尚未分析的历史基线，以及有新变化或来源背景已更新的内容；重复点击不会强制重跑当前已完成项。自动整理和“刷新并整理”继续跳过首次接入且从未分析的已读基线。

### 查看整理结果与模型路线

来源页的“整理已有数据”会显示处理中，并在结束后显示候选、完成、失败、跳过的内容项数量。没有候选时显示原因，失败时保留具体错误。最近一轮结果保存于来源，重新打开页面仍可查看。完成数按内容项统计，不代表模型调用次数；上下文不足的内容可能只标记人工介入，未调用模型。

全局配置和来源覆盖按抓取频率、Jev 轻量决策、生成与分析、独立监督、内容偏好分组。DSH 中配置了 API 连接后，还需在本插件下拉框中选择宿主已有的提供商与模型。Jev 使用独立 profile，可以在没有生成路线时完成忽略或人工介入判断。只有实际进入决策升级、拟稿或分析时才要求生成路线；监督未单独配置的字段继承生成路线。

评论先由 Jev 返回选项概率，低置信时最多调用一次生成模型升级判断。需要拟稿时才生成回复及分析摘要；PR、issue、release 分别执行审查、核实、摘要任务。摘要来自该次生成或分析的输出，没有独立的总结模型调用。Jev 的忽略、人工介入结果显示固定的分流提示，不声称生成了内容摘要。

各角色使用共用数据块与属于该角色的专属背景。当前内容保留采集原文、讨论与前版原文，不混入旧分析、草稿或会话引用。角色任务指令和额外的 decision、draft 不同。工作记录按实际发生的 Jev 调用和 DSH 角色会话展示，并保留失败原因与输入输出。

### 复用宿主模型目录与阶段背景

生成与监督模型从 DSH 的实际提供商和模型目录选择，包含宿主已注册的订阅提供商。模型列表随提供商按需读取，可以显式刷新。Jev 使用单独的 profile 下拉，保留使用 Jev 默认的选项。列表显示名称并辅助显示 ID，不需要手工填写 ID，也不会自动选择第一项。DSH 0.2.1-rc.2 的官方 DeepSeek 适配器在缺少凭据时会返回空模型列表；可先在宿主模型设置中完成配置，再显式刷新目录。插件不自行补写凭据或构造模型列表。旧选择暂不可用时保留原值并提示重新选择；切换提供商会清除相关旧模型，不能跨提供商继承全局模型。

来源配置保留现有上下文、资料、关注规则、PHI 和装配顺序作为共用背景。你可以分别为 Jev 轻量决策、低置信升级、生成与分析、独立监督补充专属上下文和资料。生成与分析按来源能力执行评论拟稿、PR 审查、issue 核实或 release 摘要，没有独立总结调用。

实际请求只装入共用背景与当前阶段的专属背景。来源预览可选择阶段，展示对应数据块；升级的 decision、监督的 draft 在预览中明确占位，实际执行时才附加真实结果。服务端解析所有显式资料以计算来源版本，预览不会触发模型。人工会话使用共用与生成分析背景，原有会话历史完整保留。

### 模型失败与持久会话

模型请求失败时，插件展示宿主记录的终止代码、消息、可用的 HTTP 状态与原会话 ID，工作记录保留实际角色会话。`TRANSPORT` 仅表示宿主报告的传输失败，不能据此断言某个网络或账号问题；插件不会自动换模型路线、改代理或凭据。

工作结束后会释放 Agent，真实会话历史仍由 DSH 持久保存。宿主可能在释放实时会话时暂时移除侧栏行，插件会通过公开的共享会话目录刷新恢复原 ID。恢复监听属于插件生命周期，离开插件页面也继续生效；只轮询已结束与人工会话的 ID 清单，不重建 Agent、不复制或补写历史。
