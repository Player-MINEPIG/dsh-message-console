# B站评论自动回复

自动回复按来源授权。编辑B站来源，开启“允许此来源自动发布评论”并保存。新来源默认关闭，学习提案不能修改这项授权。关闭来源或撤销授权会阻止尚未提交网络的发送。

## 决策与监督

评论由 Jev 在一次调用中分别判断回复方式和重要程度。回复方式分为无需回复、可自动回复、需要人工；重要程度不决定是否需要人工。低置信或含图评论升级判断一次，仍不确定时转人工。

可自动回复的评论先生成草稿，明确 `replyToCommentId` 指向根评论或某条楼中楼。插件在保存自动草稿时加入固定开头：

> 由「看点什么」插件自动回复：

独立监督检查的正文就是包含这段标识的最终正文。审查规则明确要求标识位于开头，不能改写；还需检查事实依据、用户已确认的规则、回复对象、个人立场和承诺。缺少上下文或无法判断时不通过，不反复自动改稿。监督只能批准当前绑定的草稿和版本。

## 发送条件与记录

只有本轮明确判为可自动回复、分析仍有效、当前来源已启用并授权、身份可确认、独立监督通过的新自动草稿才会发送。发送前重取平台内容核对版本，排队结束时再次同步检查授权、规则、内容、分析与草稿。代码再次检查开头标识，不依赖模型自觉遵守。

发送使用现有受保护 Cookie 中的 SESSDATA 和 bili_jct，以 aid、root、parent 精确定位评论。只允许本楼根评论或已采集楼中楼，不能自动回复自己的评论、已经回答的评论或已有发送记录的相同目标。开头标识计入1000字符正文上限。

平台成功回执必须包含可核验的评论 ID 和对应的根评论、父评论。成功后记录自动发布方式、目标、正文指纹和回执。网络超时、无效响应、回执缺失或验证码导致结果不明确时保留 `unknown`，交给用户核实，不自动重发。平台明确拒绝或请求提交前取消时保留草稿与错误。

历史草稿不会因开启授权、重新启动或重新监督而批量补发。人工会话和普通工作区会话保存的草稿继续走人工审核。GitHub 的发送权限和能力保持独立。

接口实现参考作者维护的 [OpenCLI 评论发送源码](https://github.com/jackwener/opencli/blob/main/clis/bilibili/comment.js)和[认证请求源码](https://github.com/jackwener/opencli/blob/main/clis/bilibili/utils.js)。
