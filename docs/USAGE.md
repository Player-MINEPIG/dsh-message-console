# 使用指南

## 来源与工作区

“看点什么”位于 DSH 左侧插件区域，点击后在右侧主面板展示。每个来源必须选择一个已有 DSH 工作区。分析、监督和人工处理会话均在该工作区创建，并登记到宿主工作区的会话列表。更换来源工作区仅影响新会话。工作区删除或目录失效时会停止新建工作会话，并提示重新选择；旧数据与会话链接保留。

添加来源时先输入仓库或视频链接，再选择内容类型。离开链接输入框后，插件读取标题、简介和主题或分类，建议最多12个标签。B站在视频元信息后读取真实视频标签，再加入可用分类和评论类型。标签读取失败时保留标题与简介并提示手动补充，不自动重试。GitHub 支持仓库、issues、pulls 和 releases 列表链接，单条内容链接会被拒绝；B站支持完整视频链接、BV号和av号。关注规则、阶段背景与补充指令来自本地固定模板，元信息读取失败时仍可使用。手改或手动清空的字段会保留，已有来源只在点击“重新识别并填充空白”时填充空白字段。你仍需手动选择工作区并保存；元信息读取不抓取内容、不整理，也不调用模型。

## 总览与来源页面

顶栏提供“总览”“学习记录”“全局配置”和“添加来源”。“学习记录”跨来源展示历史批次及待确认提案；在来源详情点击“整理用户评价”会直接发起该来源的学习批次并打开对应记录。总览首先显示综合优先级最高的最多三个已有平台，再显示来源卡片。点击“全部平台”或“展开来源”可单独浏览对应列表。点击平台查看该平台的来源，点击来源进入独立来源页。编辑来源入口位于来源页，全局配置只管理全局默认值。

未读变化按内容项计数，一条评论对话无论新增多少条回复都只计一个未读内容项。需要处理按内容项去重，包含待处理、整理错误及尚未确认关注的审核草稿。标记“已处理”会确认当前关注，保留现有草稿与历史，现有草稿不会再次顶起待处理提示；后续新内容、分析或草稿等事件会重新提醒。

总览来源综合排序按当前版本的分析重要性排序，有明确依据的紧急性只作有限修正，再比较需要处理数、未读数与内容变化时间。

来源内容列表始终先显示需要处理的项，再按重要性及有依据的紧急性排序，同级按最后更新时间排列，默认新到旧，可切换旧到新。最后更新时间优先使用平台内容的 `updatedAt`，缺失时回退到采集到变化的时间；抓取时间单独显示。

GitHub 列表不提供关闭状态筛选，已关闭 / 已合并内容与开放项一起显示，仍保留平台状态标签。搜索、未读/需处理筛选都在服务端分页前应用，改变条件会回到第一页。尚未整理或内容版本已变化的项不显示过期摘要与重要性。

## 查看整理结果与模型路线

来源页的“整理已有数据”会显示处理中，并在结束后显示候选、完成、失败、跳过的内容项数量。没有候选时显示原因，失败时保留具体错误。最近一轮结果保存于来源，重新打开页面仍可查看。来源按钮只处理当前来源；独立到期的自动调度仍会处理其他来源。新整理记录标明“手动触发”或“定时触发”，旧记录无依据时显示“触发来源未知”。完成数按内容项统计，不代表模型调用次数；上下文不足的内容可能只标记人工介入，未调用模型。

全局配置和来源覆盖按抓取频率、Jev 轻量决策、生成与分析、独立监督、内容偏好分组。DSH 中配置了 API 连接后，还需在本插件下拉框中选择宿主已有的提供商与模型。Jev 使用独立 profile，可以在没有生成路线时完成忽略或人工介入判断。只有实际进入决策升级、拟稿或分析时才要求生成路线；监督未单独配置的字段继承生成路线。

评论先由 Jev 返回选项概率，低置信时最多调用一次生成模型升级判断。评论和私信的最终 `state` 超过所选 Jev profile 的字符上限（未配置时为 40,000）时，跳过 Jev，直接调用生成/分析模型做一次初步判断，保留原决策阶段的数据与资料。评论判断回复方式和重要程度；私信只判断重要程度，不拟稿、不发送、不推断紧急性。超限回退保留真实普通模型会话和跳过原因，不生成虚构概率；其他 Jev 错误不触发该回退。需要拟稿时才生成回复及分析摘要；PR、issue、release 分别执行审查、核实、摘要任务。摘要来自该次生成或分析的输出，没有独立的总结模型调用。Jev 的忽略、人工介入结果显示固定的分流提示，不声称生成了内容摘要。

各角色使用共用数据块与属于该角色的专属背景。当前内容数据块保留采集原文、讨论与前版原文。分析轮的真实输入另附当前分析和既有工作记录引用，原会话的真实历史由宿主保留，不复制其他会话事件。角色任务指令和额外的 decision、draft 不同。工作记录按实际发生的 Jev 调用和 DSH 角色会话展示，并保留失败原因与输入输出。

## 整理错误与重新整理

整理失败的条目标为“错误”并进入需要处理，同时暂停该项自动整理；来源仍继续采集。失败提示可直接打开对应条目。“重新整理”只运行当前项，成功后恢复自动整理；“暂停自动整理”也可用于普通条目。标记已读/已处理和关闭提示不会恢复自动整理。“稍后处理”已移除，原有稍后项迁移为待处理。

GitHub Issue 和 PR 的最新有效整理结果为“无需介入”时，处理状态改为“无需处理”，不受平台是否开放、关闭或合并影响。后续整理发现需要人工介入或审核的问题时，再改为“待处理”。旧的未发送草稿保留正文并标为已替代，发送中或结果不明的草稿仍保留核实提醒；阅读进度不变。升级时一次性修正当前有效的旧“无需介入”结果遗留的待处理，保留手动选择、错误及活跃草稿。

模型提交的 human 和 review 都计入需处理。卡片展示简短整理意见及回复草稿标识，详情中的判断依据、技术细节与原文默认折叠，回复草稿保留独立监督及发布操作。

手动选择“无需处理”或“已处理”会确认当前这一轮提醒，使条目退出需处理列表；不删除错误、整理意见或草稿，也不恢复已暂停的自动整理。之后产生新的整理结果、错误或草稿事件时仍可再次提醒。

GitHub 大型 PR 仍完整采集保存，直接装入模型的输入只含有界概要，文件 patch 通过 dmc_read_item 的 files/file 区段按需读取。旧会话在真实请求前使用宿主原生上下文替换收起旧的大段输入，保留完整原始事件和派生引用。临时图片转发支持 pi-ai 与 Magpie；图片不写入宿主附件或会话历史。

## 整楼无需回复

B站评论的决策针对整个根评论及已采集楼中楼，结果保存在整楼条目上，不只代表最新回复；拟稿时另用 replyToCommentId 指定回复目标。最新有效分析转为“无需回复”时，清除旧待处理/稍后状态，将尚未发送的待审、被拦截及过期草稿标为已替代，保留正文、分析和会话历史，不自动标已读。发送中或结果不明的草稿仍保留核实提醒。升级时同样一次性修正已有的有效“无需回复”条目；后续用户主动设置的处理状态仍保留，新内容或新的人工处理结论照常提醒。
