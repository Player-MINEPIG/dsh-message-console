# 用评价改进后续判断

在内容详情填写评价，再生成规则修改提案。检查提案后确认应用，后续模型调用才使用修改后的规则。

## 记录你的评价

1. 进入来源页，点击内容卡片展开详情。卡片底部的“打开原始来源”可直接访问原平台。
2. 在“我的评价”中描述具体偏差和期望。例如，“普通感谢无需回复，不需要标成高优先级”。
3. 点击“保存评价”。未保存时切换内容、关闭详情或离开页面会提醒。

成功保存非空评价后，当前内容同时变为已读、已处理，并退出“需要处理”筛选。此前的分析、草稿和工作历史仍保留，评价学习使用保存时冻结的分析与决策证据。保存评价不会发布或丢弃草稿，也不会直接应用规则修改。

后续出现新内容、新分析或新草稿等事件时，内容会重新显示相应提示；需要处理的事件会重新进入“需要处理”。这项保存行为只作用于本次成功保存的评价，不会追溯更改旧评价对应的处理状态。

保存时会核对内容版本、分析版本和评价版本。其他会话已修改评价，或内容与分析已经更新时，保存会失败，输入框保留你的修改。点击“重新加载最新评价”可放弃本地修改并读取最新记录。

首次读取评价失败时，页面显示错误，可点击“重试加载评价”重新读取。

清空输入框并保存可撤回当前评价。清空评价或保存失败都不会将内容标为已处理，也不会改变当时的阅读与关注状态。历史评价版本仍保留。

## 整理并确认修改

1. 进入需要整理的来源详情，在“用户评价学习”中查看未学习数量，点击“整理用户评价”。按钮直接为该来源创建学习批次，并打开对应记录。单次最多冻结 50 条最新的未学习评价，剩余评价留到后续批次；没有未学习评价时按钮不可用。
2. 顶栏“学习记录”展示所有来源的历史批次与待确认提案，批次标明来源名称和平台。来源详情中的“学习记录”只查看该来源；记录页不需要再次选择来源，也不会发起新批次。
3. 在历史批次中查看处理状态。会话创建后，可通过“进入实际学习会话”查看完整工作历史，完成或失败后仍可直接追问原 Agent。失败或中断的批次会显示错误，并可使用原批案例重试。
4. 查看提案的修改前后差异和案例依据。每项修改标明“当前来源”或“默认配置”。当前来源可学习专属背景、规则、知识和文字偏好；默认配置可学习学习指导、摘要语言、回复风格及PR审查重点，供新来源复用。仍继承该字段的现有来源也会跟随，有显式覆盖的来源保持自己的配置。默认学习指导进入 Jev 决策、升级判断、生成分析和独立监督四个阶段。
5. 点击“确认并应用修改”或“拒绝此提案”。应用时会再次核对提案及配置版本；配置已经改变时会拒绝覆盖。

发起整理后，如果你切换页面或继续编辑评价，返回的批次不会打断当前操作。已创建的批次可从“学习记录”查看。

应用修改会保留已有分析、评价、阅读与处理状态，不把已整理项重新加入自动或手动整理候选。新指导用于未整理内容和后续真实内容版本；在途结果及旧草稿仍需通过配置版本校验，旧草稿失效后不能直接发布。

只有应用成功后，提案引用的对应版本评价才算“已学习”。仅保存评价、生成提案、拒绝提案或产生空建议都不会标记已学习。重新编辑已学习评价会生成新版本，可再次整理。

学习会话的业务工具只能读取本批案例、当时分析和 Jev 记录并保存提案，没有应用工具。可提议修改关注规则、共用或阶段背景、来源文字资料和默认文字配置。文字资料只在来源配置中保存文字，不修改工作区文件、模型、凭据、发布授权或宿主权限。

追问保留原批次的工具权限。已经应用或拒绝的批次不能再提交新提案，讨论内容也不会直接修改配置。`dmc_read_learning` 的 `batch` 结果按 `source` 和 `global` 列出可读字段与调用示例；读取默认指导使用 `{section:"configuration",target:"global",field:"learningGuidance"}`。来源文字偏好用 `target:"source",field:"settings.replyStyle"` 等字段；默认回复风格用 `target:"global",field:"replyStyle"`。`configuration` 省略 `field` 时只返回字段索引，不返回整份配置。学习不能修改模型、凭据、执行频率、自动发送授权或固定身份披露要求。

## 扫读后清除当前提示

“全部已读”只更新当前内容版本的阅读进度，不改变待处理及待审核提示。“全部已处理”仅将当前需要处理的项标为本轮已处理，确认当前关注版本，阅读进度保持独立；之后的新内容变化、分析结果或草稿仍按正常规则产生提示。

两个按钮的范围一致：来源页覆盖该来源所有分页（包括筛选隐藏的内容），平台页覆盖该平台所有来源，总览覆盖全部来源。操作在同一事务内完成，保留分析详情、草稿、评价和工作历史，不改变原平台状态。

两个批量操作都不会发布或丢弃草稿。需要审核的草稿仍可从内容详情查看。

批量接口为 `POST /api/dsh-message-console/read-all` 和 `POST /api/dsh-message-console/handle-all`，沿用宿主所有者鉴权与 JSON 防跨站请求头。请求体用 `{sourceId}` 限定来源，或用 `{platform: "github" | "bilibili"}` 限定平台；空对象作用于全部来源。来源与平台不能同时指定，无效范围返回错误。响应 `{count}` 分别统计标记已读的内容项数和本轮完成的需处理项数；重复完成返回 0。
