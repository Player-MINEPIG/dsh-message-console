# 集中查看B站私信

在“添加来源”选择“哔哩哔哩”，将“B站内容”设为“统一私信”。无需填写视频目标。选择已有工作区并保存。插件使用已导入Cookie验证真实账号并绑定来源；一个实例仅允许一个私信来源，停用来源仍占此位置。

来源按联系人显示私信。同一联系人可包含多个主题，无需配置视频背景。列表显示最新消息摘录，详情按时间分页显示作者、收发方向、类型和发送时间。展开消息可分块查看完整原文；历史版本保留当时已采集的消息。

## 采集范围

初次采集每位联系人最近100条，后续从最新消息向旧分页，直到本地已知水位或平台可见末尾，再与本地原文合并。新增超过100条时继续翻页，不会只保存最近一页。页面失败时整轮不推进内容快照和基线。平台不再返回旧水位时，界面明确提示无法证明缺口完整，本地已采集消息仍保留。

插件不回溯初次范围之前的全部历史。首次抓取沿用已读基线规则，需点击“整理已有数据”才评定这些既有私信；后续变化正常进入整理。

更换Cookie后，登录账号必须仍与原绑定账号一致。账号不一致时采集失败，不把另一账号私信并入原来源。

插件不调用平台已读接口。“已读”和个人处理状态仅在插件内生效，不改变B站状态。

## 重要程度

自动整理仅调用一次Jev的重要程度四选项，不生成回复、内容摘要或紧急性判断。真实输入输出和概率保留在工作记录中。低置信仅标注概率不足及当前最高概率等级，不额外调用升级、拟稿或监督模型。

模型只读取该会话最近100条消息，消息正文总计最多24000字符，每条最多2000字符。实际输入记录保存消息ID范围、已存总数和截断数量；已采集原文完整保留，分页阅读不受模型范围限制。

图片和其他非文字消息显示明确占位，卡片仅使用平台已有文字和元信息。插件不下载私信媒体，不向模型提供实际图片，也不声称模型已查看图片。

“进入会话阅读”可继续讨论、分页阅读原文并保留真实DSH历史。人工阅读及评价学习使用全局生成 / 分析模型，先在全局配置选择路由。私信人工会话没有存稿工具，普通工作区也不能为私信存稿；监督与发布入口同样拒绝私信。
