# 看点什么 v1.0.0

首个正式版本面向个人使用，将 GitHub 仓库、B站视频评论和私信集中到 DSH 主面板。来源分别绑定已有工作区，复用宿主的模型、工具和真实会话历史。

## 版本范围

- GitHub 采集 issue、PR、release、讨论与状态变化，通过服务器的 gh 登录读取。已关闭及合并内容仍可整理，分析结合事件操作者和登录身份判断是否需要查看。GitHub 连接器不发布评论或审查。
- B站每条视频独立配置上下文和资料。评论支持 Jev 分流、一次低置信升级、拟稿和独立监督；新来源默认不允许自动回复。明确开启来源授权后，符合条件的评论可自动发送，并带有固定的插件身份标识。
- 一个实例支持一个账号级私信来源，按联系人保存已采集消息，仅评定重要程度。私信不拟稿、不发送、不修改平台已读状态。
- 首次采集建立已读基线，后续变化按内容版本提醒。阅读与处理状态独立，支持搜索、分页、筛选、全部已读和全部已处理。
- 分析角色跨轮复用原会话；人工处理入口优先返回实际工作会话。Jev 输入输出、工具提交、历史分析及失败记录可追溯。
- 用户评价可整理为来源或默认文字配置提案，展示差异，确认后才应用。模型不能通过学习提案修改凭据、模型路线或发送授权。
- 全局平台凭据页支持 B站 Cookie 验证保存和 GitHub 网页设备授权。全局默认配置可按来源覆盖。

## 首版稳定性改进

整理失败会显示错误并暂停该项自动整理；用户可定位失败条目，单项重新整理。手动选择无需处理或已处理会确认当前提醒，但保留失败记录及暂停状态。

失效的模型路线可回退一次到当前全局默认。单轮执行时限可在全局或来源设置为 1–1800 秒，未设置时沿用后端默认，初始为 300 秒。Jev 输入超过实际 profile 上限时，直接调用普通模型初步判断，并记录跳过原因。

大型 PR 的模型输入使用有界概要，文件及 patch 按需读取；采集原文与完整会话历史保留。评论图片使用有界私有缓存，推理图片只在内存中转发，支持 pi-ai 和 Magpie 路线。

按 Assembler → Jev → 看点什么的顺序独立安装并启用，复用同一 profile 的共享服务；本插件不携带或自动安装它们的运行时副本。共享插件各自的兼容要求仍需满足。任务插件不是依赖，订阅提供商由宿主接入；本版不承诺任意第三方提供商组合的兼容性。官方桌面端自带运行环境，支持从「插件 → 添加插件」安装；详细步骤见 [GUI 与 CLI 安装](../INSTALLATION.md#dsh-安装)。

## 安装与升级

1. 保存当前插件包、配置、插件数据目录及宿主会话历史的备份。等待本插件在途工作结束，停用并确认数据锁释放；宿主无法正常卸载时安排重启。
2. 按[安装说明](../INSTALLATION.md)启用所需宿主服务，然后安装本次验收的 `dsh-message-console-1.0.0.tgz`。不要用另行构建的包替换已验收的发布附件。
3. 启用插件，检查已有来源、阅读和处理状态、草稿、学习记录及原会话入口。检查平台凭据状态与模型选择，再进行日常采集和整理。

本版使用 SQLite schema 6。旧 JSON 与早期数据库升级规则见 [数据迁移说明](../STORAGE.md#sqlite-数据与迁移)。历史开发包可能都标为 `0.1.11`，升级和回退时应同时核对源码提交及包 SHA256。旧稍后处理状态会迁移为待处理；已有无需回复及错误后手动无需处理的状态按现有迁移规则修正，原文、分析和会话历史保留。

需要回退时，先停止新版，再恢复升级前的完整数据、配置和插件包。恢复备份会丢失备份之后新增的本地记录；外部平台已经发送的内容不会随本地回退撤销。不要同时运行两个实例操作同一数据目录。

## 已知限制

- GitHub 仍按完整快照扫描。大仓库可能耗费较多请求，API 上限、缺失 patch 或上下文不足会限制自动审查；分析不等于实际运行测试或复现问题。
- B站 Cookie 不会自动续期，平台风控和出口限制可能导致采集或发送失败。私信首次每个联系人最多采集最近 100 条，模型还有单条及总字符上限，详见 [私信说明](../PRIVATE-MESSAGES.md)。
- 发送结果为 `unknown` 时需要人工到原平台核实，不自动重发。本版不提供自动对账与恢复发送界面。
- Jev native 概率是模型自报估计，未经校准。自动化测试验证流程和权限边界，不证明模型判断准确，也不代替真实账号及具体提供商的验收。
- 多用户、邮件、新闻、自动代码修复及完整自动复现环境不在本版范围。
